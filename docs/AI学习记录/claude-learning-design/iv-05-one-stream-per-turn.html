Chapter 5 · 面试视角（5/7）

每轮一次 stream + continuation 前重载历史

"provider turn"是 opencode 里一个硬命名的原子单元：恰好一次 llm.stream(request)，流到终止，然后结算工具，然后——若要继续——从 durable log 重新投影历史，构造一个全新的请求再发一次。这不是迂腐，是因为这一轮是计费、取消、缓存断点、错误归类的共同边界。绕过它会同时破坏这五件事。

① 定位 ② 问题先于方案 ③ 设计拆解 ④ 生产级取舍 ⑤ 双视角 🎯 面试追问

1一句话定位

一个 provider turn = 恰好一次 llm.stream，它流到完成，期间产出的 assistant 文本/工具调用都增量写进 durable log；stream 结束后 join 所有工具 fiber；若需要 continuation（模型还想要更多工具结果），重新从 DB 查历史，重建请求，开下一个 turn。不存在"内存里拼一条消息接着流"。

🔑 一句话

下一轮请求是 (sessionID, baselineSeq, model) 的纯函数，没有任何隐藏的内存状态。崩溃/重启后跑同样的输入，得到同样的请求。

2问题先于方案

"legacy 单体"做法是在一个内存循环里反复调 stream、在内存数组里拼消息、工具结果直接塞回内存接着流。这个"内存工具循环"反模式生产里会崩在哪？

痛点 A · 崩溃恢复失真

工具执行完、下一轮 stream 还没发，进程崩了。内存里拼好的"下一轮 messages"没了。重启只能从 log 重建，但 log 和内存不一致——续跑的请求和崩溃前不一样。

痛点 B · 缓存前缀漂移

内存拼接路径的顺序/去重逻辑可能和 durable projector 不一致（projector 有 compaction 边界、baselineSeq 过滤）。拼出来的 messages 字节不同 → 缓存 miss。

痛点 C · 取消/中断无干净边界

没有"一个 turn"的清晰概念，stream 和工具结算交错。中断没有原子窗口，可能切在工具执行中、流到一半，留下半完成状态。

痛点 D · 并发 steer 无法注入

内存循环不查 log，steer 被持久化后内存循环看不到。要专门 inject 逻辑——而重载路径免费就拿到了（steer 已是 durable 消息）。

⚠ 共同病根

把"模型可见状态"留在内存里，而权威状态在log里。两条真相源必然发散。重载路径消灭了第二条真相源。

3设计拆解

一个 provider turn 的生命周期，以及 continuation 怎么衔接下一个 turn。

"一轮一次 stream"为什么是硬不变式（5 个理由）

① 计费单元

token/成本在终止的 finish 事件里上报。一个 turn = 一次计费。多个 stream 拼一个 turn 就没有单一计费点。

② 取消单元

一个 turn = 一个可中断的 stream。中断打在这个边界上，干净。

③ 缓存断点

"到这轮为止的请求体"是 prompt cache 的缓存对象。一个 turn 一个断点。

④ 错误归类

一个 LLMError 映射到一个 retry-or-fail 决策。turn 是错误处理的粒度。

⑤ 工具分组

一个 turn 里的所有 tool call 一起结算，然后才 continuation。批次原子。

📌 TurnTransition 是例外，不是规则

compaction / overflow-compaction 是唯一能打断"一轮一次"的信号，它们用 TurnTransitionError defect 表达，被 runTurn 捕获后重新进入 runTurn（重新 reload、重建请求）——而不是在 stream 中间 mutating 状态。例外也走重载路径。

4生产级取舍

每轮重载历史看起来"浪费"（多一次 DB 查询），但它消灭了一整类一致性 bug。

选择：每轮从 DB 重投影

  • 下一轮请求是纯函数，无隐藏状态
  • 崩溃续跑必然一致（DB 是唯一真相）
  • 缓存前缀字节稳定（projector 确定性）
  • steer 持久化后免费出现在下轮

内存拼接的代价

  • 内存与 log 双真相源 → 发散
  • 崩溃续跑请求失真
  • 拼接逻辑≠projector → 缓存 miss
  • steer 要专门 inject 逻辑
🔑 本质

重载不是性能负担，是一致性保险。一次 DB 查询（毫秒级）换来"下一轮请求绝对正确"——对比一次 LLM 调用（秒级、贵），这个保险几乎免费。

5面试双视角

这题考的是抗失败设计 + 不变式思维——你能不能识别"一轮一次 stream"是个不变式，以及为什么 continuation 必须重载。

🎙️ 面试官为何问这题

  1. 探你有没有"单一真相源"直觉——内存 vs log 双真相会发散。
  2. 探不变式思维——能不能说出"一轮一次"对应的多个理由（计费/取消/缓存/错误/工具）。
  3. 探崩溃恢复——续跑怎么保证请求一致？
  4. 埋雷：很多人答"重载浪费 DB 查询"。追问"对比一次 LLM 调用的成本呢？"——看你能不能答出"保险几乎免费"。

🧑‍💻 面试者拆解（五段式）

  1. 抽象定位：provider turn 是计费/取消/缓存/错误/工具的共同原子边界，所以"一轮一次 stream"是硬不变式。
  2. 讲约束：continuation 必须从 DB 重投影，下一轮是 (sessionID, baselineSeq, model) 的纯函数。
  3. 讲收益：单一真相源（DB）；崩溃续跑必然一致；缓存稳定；steer 免费注入。
  4. 主动讲代价：每轮多一次 DB 查询。但对比 LLM 调用成本（秒级、贵），这个毫秒级保险几乎免费。
  5. 给未来演化：重载路径是"function of log"——未来加 compaction、加 epoch、加新消息类型，都只在 projector 一处改，continuation 主循环不动。
✅ 加分项

主动联系前几篇："重载历史用的是 iv-03 的 baselineSeq 锚点（保证 baseline+历史原子对子）；steer 免费注入依赖 iv-04 的'durable 消息'设计；turn 边界正是 iv-04 promote steer 的安全点。"——这五篇是一个一致性体系的不同侧面。
