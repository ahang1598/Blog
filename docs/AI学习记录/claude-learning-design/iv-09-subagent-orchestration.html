Chapter 9 · 智能体与工具（2/4）

子智能体编排与权限收窄

父 agent（有完整 bash/write 权限）想委派一个"只读搜索"任务给一个子 agent。如果子 agent 直接继承父的权限，它一旦幻觉出写命令就能改仓库——最小权限委派破产。opencode 的解法：子 agent 是独立 session + 权限在 spawn 时减法收窄（继承父的 deny + 自己的上限 + 防递归默认禁），且结果通过 durable log 回流，而非内存返回值。

① 定位 ② 问题先于方案 ③ 设计拆解 ④ 生产级取舍 ⑤ 双视角 🎯 面试追问

1一句话定位

子 agent 是父 agent 通过 task 工具调用派生出的独立 session。它的权限不是继承父的全部，而是在 spawn 时减法收窄：父的 deny + 外部目录规则 + 子 agent 自己的上限 + 默认禁 task/todowrite。结果通过 durable log 回流父 session（前台等完成、后台注入合成消息），绝不作为内存返回值。

🔑 一句话

委派 ≠ 共享权限。委派 = 把权限收窄到子任务所需的最小集，并保证结果可恢复、可审计、可终止。

2问题先于方案

如果子 agent 直接继承父的全部权限、结果作为内存返回值返回，生产里会怎样？

痛点 A · 权限提升（privilege escalation）

父 agent 有 bash/write。子 agent 是"只读探索者"，但继承父权限后，模型一旦幻觉出写命令就能改仓库。最小权限委派形同虚设，"只读"只是提示词里的口号。

痛点 B · 递归风暴

子 agent 没有 task 工具的限制，可以 spawn 自己的子 agent，子又 spawn 子……无限递归，资源耗尽。或子 agent 抢占 todowrite 造成 todo 列表竞态。

痛点 C · 结果随崩溃丢失

子 agent 的结果作为内存返回值。父进程在等待时崩溃——子 agent 可能已经执行了有副作用的操作（改了文件、发了请求），结果和影响都无 durable 记录，无法审计、无法恢复。

痛点 D · 委派深度无界

没有深度限制，父→子→孙→… 一条链可以无限延伸，每层都消耗 token 和工具调用。成本和复杂度失控。

⚠ 共同病根

把"委派"当成"共享一切"。但委派的本质是在更小权限范围内完成一个子任务——共享权限违背了委派的初衷。

3设计拆解

三层防护：spawn 时的减法收窄 + 递归/竞态默认禁 + 独立 session + durable 回流。

三层防护详解

① 减法收窄权限

子权限 = 父的 deny ∩ 子的上限。子永远不能超过自己声明的权限，且继承父的硬 deny。交集语义保证只读探索者物理上拿不到 write/bash。

② 防递归 + 防竞态默认禁

默认禁 task（子不能再 spawn 子，防递归风暴）+ todowrite（防与父的 todo 列表竞态）。除非子 agent 显式允许，否则这两个能力不存在。

③ 深度限制 + durable 回流

沿 parentID 链回溯，超过 subagent_depth（默认 1）拒绝。结果通过 durable log 回流（前台等完成 / 后台注入合成消息），崩溃也不丢。

📌 减法收窄的关键：交集语义

不是"父权限 + 子权限"的并集（那会让子更强），而是交集——子只能拥有"父允许 且 子声明"的能力。父禁的，子必禁；子没声明的，子也没有。最小权限是构造出来的，不是运行时检查的。

4生产级取舍

减法收窄牺牲了灵活性（子不能比父强），换来安全性和可恢复性。

选择：减法收窄 + 交集语义

  • 只读探索者物理上不能写
  • 子永不超过自己声明的能力
  • 父的硬 deny 强制下传

继承父全部权限的代价

  • 权限提升：子幻觉写命令就改仓库
  • "只读"沦为提示词口号
  • 最小权限委派破产

选择：durable 回流 + 深度限制

  • 结果随崩溃不丢，可审计可恢复
  • 委派深度有界，成本可控
  • 前台/后台两种回流模式

内存返回 + 无深度限的代价

  • 崩溃=结果和影响全丢
  • 递归风暴，资源耗尽
  • 无法审计子 agent 做了什么
🔑 本质

子 agent 编排的核心是把"委派"从权限共享变成权限收窄 + 独立可恢复执行。每个子任务是隔离的、最小权限的、durable 的一次执行——失败不会污染父，崩溃不会丢结果。

5面试双视角

这题考的是安全设计 + 分布式系统直觉——你懂不懂最小权限委派、懂不懂结果不能靠内存传递。

🎙️ 面试官为何问这题

  1. 探最小权限直觉——子 agent 该有什么权限？继承父的对不对？
  2. 探分布式恢复直觉——子任务结果怎么回父？崩溃了怎么办？
  3. 探终止性思维——子能 spawn 子吗？递归怎么终止？
  4. 埋雷：很多人答"用子进程隔离"。追问"子进程崩溃了结果呢？"——看你能不能答出"durable log 回流，不能靠内存返回"。

🧑‍💻 面试者拆解（五段式）

  1. 抽象定位：子 agent 是父通过 task 工具派生的独立 session，权限减法收窄（交集），结果 durable 回流。
  2. 讲约束：交集语义（子永不超自己声明）；默认禁 task/todowrite；深度限制；前台等/后台注入两种回流。
  3. 讲收益：最小权限是构造的（非运行时检查）；递归有界；结果崩溃不丢、可审计。
  4. 主动讲代价：子能力受限（不能比父强）；独立 session 有开销。但远小于"权限提升/递归风暴/结果丢失"的代价。
  5. 给未来演化：subagent_depth 和权限规则可配置——未来可支持"分层委派"（探索→分析→执行），每层不同权限 ceiling。
✅ 加分项

主动联系 iv-02："子 agent 是独立 session = 它有自己的 durable log。这和 iv-02 的'admission vs execution 分裂'是同一个可靠性体系——子任务也是 durable admission + execution，崩溃后能从子的 log 恢复。委派不是函数调用，是 durable 的子执行。" 能把委派和持久化执行打通，是高级信号。
