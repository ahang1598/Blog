Agent 框架设计精解 · 学习计划 19 篇设计级深度解析 · 面试双视角 · 递进追问自测 · 从设计哲学而非代码细节理解生产级 Agent 框架

这套文档回答一个核心问题:一个生产级 Agent 框架为什么是这样设计的?每个子系统要解决的真实痛点是什么?面试官问这些问题究竟在考察什么深度?

和"读源码"不同,这里屏蔽所有代码实现细节——不出现文件路径、不贴函数源码、不说"第 X 行做了 Y"。只讲分层契约、设计决策、生产取舍、备选方案对比。每篇贯穿面试双视角:面试官为何问 + 面试者如何答出生产洞察。

这套文档不做什么(读前必读)

  • 不讲代码实现——没有 file:line、没有函数源码、没有"这个函数怎么写的"。实现可交给 AI,设计判断不能。
  • 不是 API 文档——不教你怎么用框架,讲的是框架本身为何存在。
  • 不是 demo 教程——每个设计点都落到"生产中为何必须这样,简单做法为何会在真实负载下崩"。
  • 不回避取舍——每个设计都显式命名它接受了什么代价。生产设计没有银弹。

阶段 1

建立全景 · 谁是谁

⏱ 约 1.5–2 小时 · 前置:了解 LLM 与 tool calling 基本概念 · 目标:能画出 Agent/Session/Run 三者关系图,能说清整体分层

要解决的问题:绝大多数人把"Agent"当成一个模糊的词,把一次对话、一次推理、一个持久身份搅成一团。这个阶段把概念边界划清楚——后面所有设计都建立在这三个概念能分清的前提上。

读完要能回答:

  • Agent / Session / Run 三者各自的生命周期是什么?为什么必须分开建模?
  • "一次 Agent 调用"在产品语义上到底指哪一层?
  • 整体架构为什么是三层?Gateway 为什么是单中枢?

本阶段文档:

① Agent/Session/Run 三概念辨析 ⑰ 整体分层与 Gateway 中枢
阶段 2

智能核心主线 · 一次推理如何完整跑完

⏱ 约 6–8 小时 · 前置:完成阶段 1 · 目标:能完整复述"用户发一条消息 → 最终交付给模型 → 工具循环 → 任务完成"的全链路设计决策

要解决的问题:这是 Agent 框架的"心脏"。每篇都对应面试高频题:"Prompt 怎么拼的""工具怎么调用的""对话太长怎么办""agent 怎么记住东西"。但生产答案和 demo 答案天差地别。

读完要能回答:

  • 为什么推理循环要拆 turn/attempt/run 三层?每层各 owns 什么?
  • Prompt 的稳定前缀为什么值钱?provider 的私有调优如何不污染核心?
  • 工具契约为什么必须用类型 schema?tool_use/tool_result 配对为什么是硬不变量?
  • 上下文压缩为什么用摘要式而非滑动窗口?为什么要迭代更新而非重算?
  • 记忆和压缩的本质区别是什么?为什么不抄经典 episodic/semantic 记忆图?
  • Skills 如何让 agent 运行时获得新能力而不撑爆 prompt?
  • 思维链(thinking)为什么不能当普通文本处理?
  • 为什么模型 token 流不能直接送给聊天协议?

本阶段文档(9 篇,核心):

② 推理循环:三层嵌套设计 ③ Prompt 拼接设计 ④ 工具系统设计 ⑤ 上下文压缩设计 ⑥ 多层记忆架构 ⑦ Skills 动态能力系统 ⑧ 推理模型与思维链处理 ⑨ 流式架构设计
阶段 3

协作与可靠性 · Agent 怎么不崩、能分工

⏱ 约 4–5 小时 · 前置:完成阶段 2 · 目标:理解生产 Agent 在并发、故障、委派场景下的设计约束

要解决的问题:单线程、单 Agent、永远成功的 demo 跑通后,真实世界的并发、超时、用户中途取消、子任务派发会把所有简单设计打回原形。这个阶段讲"Agent 怎么活下来"。

读完要能回答:

  • 子 Agent 为什么是"另一个 session"而不是"更小的运行时"?push-based 完成为何优于轮询?
  • Hooks 在哪些阶段插入?阻塞型与观察型有何区别?
  • 为什么终端状态要"优先级格"而不是 if/else 链?为什么取消要 sticky?
  • 为什么按 session-key 串行?子 Agent 改同一文件谁赢?
  • 重试在 attempt 级和 run 级边界在哪?什么操作绝对不能重试?

本阶段文档(5 篇):

⑩ 子 Agent 与任务委派 ⑪ Hooks:生命周期扩展点 ⑫ 中断、中止与终端状态优先级格 ⑬ 并发模型:lanes 与会话串行化 ⑭ 重试、回退与故障容忍设计
阶段 4

身份与自主性 · Agent 的人格、记忆与主动性

⏱ 约 2.5–3 小时 · 前置:完成阶段 2-3 · 目标:理解 Agent 如何成为"持续存在、有个性、能主动"的实体,而非一次性问答机

要解决的问题:Agent 的产品价值很大程度来自"它记得你""它有自己的人格""它不等被问才动"。这些能力背后是冷启动、身份稳定性、自主性安全边界等设计问题。

读完要能回答:

  • 冷启动时 Agent 的人格/指令/用户档案从哪来?如何"热身"?
  • 截断 bootstrap 文件与保持稳定身份之间如何取舍?
  • Agent 如何定时巡检、主动汇报、后台巩固记忆?
  • 主动行为(发消息、执行副作用)的安全边界在哪?

本阶段文档(2 篇)+ 平台支撑(2 篇):

⑮ Agent 身份、人格与冷启动 ⑯ 自主性:heartbeat、主动委派、后台巩固 ⑱ 插件系统:扩展点与隔离边界 ⑲ Provider 路由:API family 抽象

📚 系统精读(约 14 小时)

按阶段 1→2→3→4 顺序全读

每篇固定 7 节结构

  1. 设计问题 — 生产中要解决的真实痛点(不是 demo 玩具)
  2. 分层设计 — 一张概念架构图(讲职责划分,不讲代码结构)
  3. 为何这么设计 — 生产动机 + 备选方案对比 + 显式命名取舍
  4. 完整示例 — 一次概念性 worked example(产物形态 + 推理链路,不贴代码)
  5. 面试官视角 — 考察什么深度;浅答 vs 深答的分水岭
  6. 面试者视角 — 如何结构化作答;主动展现哪些生产洞察
  7. 递进追问测验 — 5 题层层下钻,可显示参考答案
