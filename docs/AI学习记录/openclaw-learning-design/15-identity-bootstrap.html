一 · 设计问题:agent 第一次启动时"是谁"

一个新部署的 agent,没有任何对话历史。它第一次接到用户消息时,必须立刻知道自己是谁:叫什么名字、什么人格、能做什么不能做什么、用户是谁、项目背景、工作纪律。否则它就是个"失忆的通用 LLM",每次都从零开始,行为不可预测。

这些"身份信息"从哪来?demo 级做法:硬编码在系统 prompt 里。但生产中:

  • 不同用户/项目身份不同:你给 Alice 的 agent 和给 Bob 的 agent,人格、偏好、项目都不同。硬编码一套不行。
  • 身份要可演化:用户说"以后别用 any 类型",这个偏好要持续影响身份,不能下次对话又忘了。
  • 身份可能很大:详细的工作纪律、用户档案、项目规范,加起来可能几万字。全塞 prompt 爆。
  • 身份要稳定:同一 agent 跨对话人格要一致,不能这次严谨下次随意(见第③篇缓存也依赖此)。
  • 多源拼装:身份来自多处——项目级指令、用户级偏好、agent 人格、记忆种子。要有序拼装。

二 · 分层设计:bootstrap 文件栈

┌──────────────────────────────────────────────────────────────────────┐ │ 身份冷启动 · bootstrap 文件栈 │ └──────────────────────────────────────────────────────────────────────┘ [启动时扫描身份文件 · 按优先级和限额注入] ┌──────────────────────────────────────────────────────────┐ │ AGENTS.md / CLAUDE.md ← 项目级工作纪律、编码规范 │ 最高优先 │ "提交前跑测试、用 pnpm、不要 any" │ └──────────────────────────────────────────────────────────┘ ┌──────────────────────────────────────────────────────────┐ │ SOUL.md ← agent 人格定义 │ │ "你是 Molty,严谨、直接、爱用比喻" │ └──────────────────────────────────────────────────────────┘ ┌──────────────────────────────────────────────────────────┐ │ USER.md ← 用户档案 │ │ "用户是 Alice,资深前端,偏好 TypeScript/React" │ └──────────────────────────────────────────────────────────┘ ┌──────────────────────────────────────────────────────────┐ │ MEMORY.md ← 长期记忆种子(第⑥篇) │ │ "用户上次说过不喜欢任何、项目根目录在..." │ └──────────────────────────────────────────────────────────┘ ┌──────────────────────────────────────────────────────────┐ │ IDENTITY.md / TOOLS.md / HEARTBEAT.md / BOOTSTRAP.md │ 辅助 │ 身份细节、工具指引、主动任务、额外启动指令 │ └──────────────────────────────────────────────────────────┘ ↓ 按优先级 + per-file 限额 + 总限额 注入 [冷启动组装] → 这些文件内容进入 system prompt 的稳定前缀(第③篇) → 跨对话稳定 → 缓存命中 + 身份一致

三层限额机制

限额作用典型值
per-file 限额单个文件不能太大~20000 字符
总限额所有 bootstrap 加起来有上限~60000 字符
截断标记超出时明确告知"已截断""[本文件已截断 N%]"

三 · 为何这么设计:三个核心决策

决策 1:为什么用文件而非配置/数据库

身份信息用文件(AGENTS.md 等)而非数据库或 config,因为:① 可读可编辑——用户/开发者直接看改,版本控制跟随项目;② 项目级 vs 用户级分离——AGENTS.md 跟项目走(团队共享),USER.md 跟用户走(个人偏好);③ 启动时加载——文件是静态的,启动扫描即可,无需运行时查询;④ 可演化——agent 可以写回这些文件(如更新 MEMORY.md)实现身份演化。文件 = 身份的可读、可版本、可演化的载体。

决策 2:为什么分层 + 限额

身份信息来源多(项目/人格/用户/记忆),且总量可能很大。分层让每类身份有明确归属(AGENTS 管纪律、SOUL 管人格、USER 管档案、MEMORY 管记忆),便于独立维护和优先级排序。限额防止某个文件(如超详细的 AGENTS.md)吃光整个 prompt 预算。per-file 限额 + 总限额 + 截断标记,把身份注入约束在可控范围。取舍:截断会丢部分身份信息(模型不知道截断的内容),但比撑爆上下文窗口强。优先级排序保证最重要的(纪律、人格)先注入,辅助的(详细记忆)满了可截。

决策 3:截断与稳定身份的张力

这是个微妙的矛盾:身份要稳定(缓存命中),但截断会让身份"部分不稳定"——如果 AGENTS.md 内容变化导致截断点变了,注入的部分也变了,破坏缓存。缓解:① 稳定前缀策略——按优先级注入,高优先级的不太可能被截(给足限额),低优先级的截断变化只影响尾部;② 截断点确定性——截断按字符数硬切(不依赖内容分析),同一文件同样大小截同样位置;③ bootstrap 钩子——允许运行时动态调整哪些文件入选(适配场景),但调整要受控。这个张力不可完全消除,只能用限额 + 优先级把不稳定约束在尾部。这是身份系统的一个固有取舍。

核心取舍:bootstrap 文件栈带来文件管理、限额计算、截断处理的复杂度,换来的是身份可读可演化、多源有序拼装、跨对话稳定。替代方案(硬编码/数据库)的失败模式是"不可定制/不可演化/启动查询开销/身份漂移"。接受复杂度,因为'agent 是谁'是产品差异化的核心——一个有稳定身份的 agent 比通用 LLM 有价值得多。

四 · 完整示例:一次冷启动的身份组装

新部署的 agent 给用户 Alice(前端工程师,项目 myproject)。第一次接到消息时,冷启动组装身份:

[启动扫描] 在工作区和用户目录找身份文件 发现: · /Users/alice/myproject/AGENTS.md (项目纪律, 8000 字符) · /Users/alice/myproject/SOUL.md (agent 人格, 2000 字符) · ~/.openclaw/agents/agent-1/USER.md (用户档案, 3000 字符) · ~/.openclaw/agents/agent-1/MEMORY.md (长期记忆, 5000 字符) [限额检查] per-file 都 < 20000 ✓ 总量 = 8000+2000+3000+5000 = 18000 < 60000 ✓ 无需截断 [按优先级注入 system prompt 稳定前缀] [SOUL.md] "你是 Molty,严谨直接,爱用比喻..." [AGENTS.md] "工作纪律:提交前跑测试,用 pnpm,禁 any..." [USER.md] "用户 Alice,资深前端,偏好 TS/React..." [MEMORY.md] "用户上次说不喜欢 any,项目用 vitest..." [结果] · agent 立刻"知道自己是谁、为谁服务、怎么工作" · 这段跨对话稳定 → prompt 缓存命中 + 身份一致 · 用户说"以后代码加注释" → agent 更新 MEMORY.md → 下次启动身份演化
关键洞察:冷启动让 agent 从"失忆通用 LLM"变成"有身份、有记忆、有纪律的专属助手"。整个过程是文件扫描 + 限额 + 优先级注入,无数据库查询开销。且因为身份在文件里,用户/开发者可读可改可版本控制。agent 写回 MEMORY.md 实现身份演化——这次对话学到的偏好,下次启动就生效。

五 · 面试官视角:这题在考察什么

回答层次面试官的判断
"系统 prompt 写死身份""没考虑多用户/演化"
知道要存用户偏好"有意识但没系统"
能说分层文件 + 注入"及格"
能谈限额、截断张力、文件可演化、缓存稳定性"生产经验扎实"

六 · 面试者视角:如何答出生产洞察

结构化作答模板:
  1. 先点需求:"新 agent 启动必须立刻知道'我是谁、为谁服务、怎么工作',否则是失忆通用 LLM。"
  2. 给文件栈:"用 bootstrap 文件——AGENTS(纪律)、SOUL(人格)、USER(档案)、MEMORY(记忆种子)。启动扫描,按优先级注入 system prompt 稳定前缀。"
  3. 主动谈为何文件:"文件可读可编辑、版本控制、项目级vs用户级分离、agent 可写回实现演化。比数据库轻、比硬编码灵活。"
  4. 主动谈限额:"per-file + 总限额 + 截断标记,防某个文件吃光预算。优先级保证最重要的先注入。"
  5. 主动谈张力:"截断与稳定身份有张力——截断点变会破坏缓存。用稳定前缀 + 确定性截断把不稳定约束在尾部。"
