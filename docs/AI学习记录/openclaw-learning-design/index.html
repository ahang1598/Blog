Part A

Agent 智能核心

9 篇 · 回答"一次推理如何完整跑完"
① 阶段 1 · 起点 地基
Agent / Session / Run 三概念辨析
人们最常混淆的三个概念。三者各自的生命周期、数量关系、为何必须分开建模。失败作用域、压缩归属、重试边界。
② 阶段 2 · 核心 高频
推理循环:三层嵌套设计
turn/attempt/run 各 owns 什么。为什么"一次推理""可重试尝试""故障兜底"要拆三层。每层 owns 什么故障。
③ 阶段 2 · 核心 高频
Prompt 拼接设计
缓存经济学(稳定前缀为何是钱)。provider 注入如何不污染 core。完整拼接的概念产物形态。模型身份为何放后面。
④ 阶段 2 · 核心 高频
工具系统设计
类型 schema 契约。串行/并行派发(一个 sequential 为何降级整批)。tool_use/tool_result 配对为何是硬不变量。幂等性。
⑤ 阶段 2 · 核心 高频
上下文压缩设计
摘要式 vs 滑动窗口的生产取舍。为何迭代更新旧摘要而非重算。turn 边界感知。故障容忍降级链。结构化模板锚点。
⑥ 阶段 2 · 核心 高频
多层记忆架构
记忆 vs 压缩的本质区别。为何不抄经典 episodic/semantic 图。四层栈 + 混合检索。dreaming 短期→长期巩固。置信度筛选。
⑦ 阶段 2
Skills 动态能力系统
运行时如何获得新能力而不撑爆 prompt。索引注入 + 按需加载。版本化资源。触发条件。skill vs 工具的区别。
⑧ 阶段 2
推理模型与思维链处理
thinking 为何不能当普通文本。独立字段、透传策略、压缩优先丢、预算分级。completedBeforeOrAtTimeout 精神。
⑨ 阶段 2
流式架构设计
双层流(模型 token vs channel block)。为何不 token 直送聊天协议。切分优先级链。代码块不撕裂。preview 取舍。
Part B

Agent 协作与可靠性

5 篇 · 回答"怎么不崩、能分工"
⑩ 阶段 3
子 Agent 与任务委派
递归 session 模型(子=另一个 session,非更小运行时)。push-based 完成为何优于轮询。工具策略单调继承。共享工作树。
⑪ 阶段 3
Hooks:生命周期扩展点
各阶段钩子。阻塞型 vs 观察型。终止语义(proceed/block/cancel/modify)。串行确定性。fail-closed。核心保持纯净。
⑫ 阶段 3 · 核心 高频
中断与终端状态优先级格
为何终端状态要闭式优先级格(timeout>cancelled>failed)。sticky 规则。单一真相源。证据优先于时间戳的例外。
⑬ 阶段 3
并发模型:lanes 与会话串行化
按 session-key 串行的最小串行化原则。跨进程写锁。子 agent 独立 lane。acquire 超时与死锁预防。防止 race。
⑭ 阶段 3
重试、回退与故障容忍
attempt/run 重试边界。故障分类(瞬态vs永久)。凭据轮转。非幂等操作绝不自动重试(红线)。退避抖动防风暴。预算控制。
Part C

Agent 身份与自主性

2 篇 · 回答"怎么成为持续存在、能主动的实体"
⑮ 阶段 4
Agent 身份、人格与冷启动
bootstrap 文件栈(AGENTS/SOUL/USER/MEMORY)。为何用文件。分层限额 + 截断。截断与稳定身份的张力。身份演化与安全。
⑯ 阶段 4
自主性:heartbeat、主动委派、后台巩固
agent 如何不被问才动。heartbeat/cron/dreaming 三机制。可逆性权限分级。注入风险。错误汇报。自主成本控制。
Part D

平台支撑(最小必要)

3 篇 · 回答"整体怎么切分才不烂"
⑰ 阶段 1
整体分层与 Gateway 中枢
三层切分(可复用库/编排/插件)。core 为何必须 plugin-agnostic。Gateway 单守护进程。单点风险 vs 分布式复杂度。seam 设计。
⑱ 阶段 1
插件系统:扩展点与隔离边界
控制面/运行时面分离。manifest 先于代码。注册事务化。插件不能 import 核心内部。崩溃隔离。依赖管理。
⑲ 阶段 1
Provider 路由:API family 抽象
为何按 API family 而非 provider-id 路由(解耦点选择)。harness 选择 fail-closed vs auto。specifics 隔离在插件。本地/云混合。

这套文档的设计哲学

  • 设计级,非代码级——绝不出现 file:line、函数源码、"第 X 行做了 Y"。只讲分层、契约、决策、取舍、生产动机。
  • 面试双视角——每篇含「面试官为何问(考察什么深度)+ 面试者如何答(展现什么生产洞察)」。
  • 生产而非 demo——每个设计点落到"生产中为何必须这样,简单做法为何会在真实负载下崩"。
  • 不回避取舍——每个设计都显式命名它接受了什么代价。生产设计没有银弹。
  • 测验递进下钻——模拟面试官层层追问,逼到生产取舍层面,巩固理解。

每篇固定 7 节结构

  1. 设计问题 — 生产中要解决的真实痛点
  2. 分层设计 — 一张概念架构图(讲职责,不讲代码)
  3. 为何这么设计 — 生产动机 + 备选方案对比 + 显式命名取舍
  4. 完整示例 — 一次概念性 worked example(产物形态 + 推理链路)
  5. 面试官视角 — 考察什么深度;浅答 vs 深答的分水岭
  6. 面试者视角 — 如何结构化作答;主动展现哪些生产洞察
  7. 递进追问测验 — 5 题层层下钻,可显示参考答案
