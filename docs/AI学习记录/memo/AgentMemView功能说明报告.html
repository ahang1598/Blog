AgentMemView 功能实现说明报告

本地单机的编码 Agent 记忆系统：通过透明代理沉淀对话记忆、提供可观测的记忆血缘与检索轨迹、离线优先设计。本报告基于对 packages/ 全部七个包源码的逐文件调研，完整梳理其功能实现。

架构形态 pnpm monorepo · 7 packages 核心栈 TypeScript · Hono · SQLite(WAL+FTS5+sqlite-vec) 前端 React 19 + Vite 7 端口 proxy :8619 / core :8620 许可 MIT
01

项目概览

README · docs/architecture.md

AgentMemView 是一套面向编码 Agent（Claude Code / Codex / OpenCode）的本地单机记忆系统，核心闭环为：

  • 透明代理接入（:8619）：Agent 把 base-url 指向代理，代理在对话链路上完成「记忆注入 → 上游转发 → 响应捕获 → 脱敏写回」，业务路径零感知；
  • 四级记忆分层：L0 原始消息 → L1 原子事实 → L2 场景索引 → L3 用户画像；
  • 混合检索：FTS5 trigram BM25 与 sqlite-vec 余弦双通道 + RRF 融合 + 艾宾浩斯衰减，检索期零 LLM 调用；
  • 全程可观测：每次检索的六阶段决策完整落盘（retrieval traces），注入记录逐轮 MD5 监控，Dashboard 实时回放；
  • 离线优先：不开启任何选配能力时全功能离线可用，所有外部依赖（LLM/Embedding/Sidecar）失败一律降级而非报错。

数据模型与记忆分层

所有记忆查询被 Scope{serviceId, spaceId, agentId?} 信封强制约束（ScopedDao 构造校验），SQL 层面绑定 space_id = ? AND (agent_id IS NULL OR agent_id = ?) —— agent_id IS NULL 表示空间共享，结构性杜绝裸跨空间查询。

四级记忆分层

L0 原始消息 l0_messages

对话原文逐轮落库：session、turn、seq 分块序号、role、content、redacted（脱敏命中数）、token_count。写入前完成脱敏 + 信封剥离 + 8192 字符定长分块。仅作溯源与血缘锚点，永不自动注入。

L1 原子事实 l1_facts

记忆检索单元。content + SHA-256 content_hash + 三态 status（active/superseded/forgotten）+ pinned + confidence + half_life_days + access_count + superseded_by 自引用链。编辑即 supersede（不删旧行），遗忘可恢复。

L2 场景索引 l2_scenarios

每场会话的标题 + 200 字摘要 + token 预估。注入时只注入索引行，全文按需经 memory_search 读取——控制每轮注入成本。

L3 用户画像 l3_profiles

按 scope_key + version 追加式版本化存储 Markdown 画像。每轮全文注入最新版，保证注入前缀字节稳定（支撑上游 KV-cache 命中）。

存储引擎细节

  • 打开即加固：journal_mode=WAL（写时并发读）+ foreign_keys=ON + sqlite-vec 扩展加载；加载失败由 doctor 命令翻译为可操作指引。
  • 版本链迁移器：扫描 migrations/*.sql 按名排序，跳过已应用项，每个迁移事务内执行 + 记录 schema_migrations，失败整体回滚。
  • 稳定游标分页：默认 50 条、硬上限 200；cursor = 上页末条 id，rowid 定位；多取 1 条判断 hasMore。
  • .mempack 迁移包：格式 agentmemview-mempack/1 = tar.gz{ manifest.json + agentmemview.db }。导出走 SQLite online backup 得一致快照；导入时维度不匹配的向量不拒绝，写入 config.pending_rebuild 标记待重建。tar 实现为零依赖 ustar 子集。

六阶段检索管线

retrieval/engine.ts · 检索期零 LLM
STAGE 1预过滤scope SQL 过滤
status='active'
STAGE 2双通道并行FTS5 BM25 ∥ vec 余弦
各取 100 → 截 30
STAGE 3RRF 融合k=60 倒数排名
STAGE 4衰减+实体艾宾浩斯 × 分数
实体命中 +0.1
STAGE 5Top-K默认 8 条
STAGE 6留痕全阶段落盘
retrieval_traces

通道一：FTS5 trigram（keyword.ts）

查询按 Unicode 属性 [^\p{L}\p{N}_-]+ 切词（CJK 友好），仅保留 ≥3 码点的词（trigram 下限），双引号包裹为短语以 OR 连接（偏召回）；无合格词时自动降级 LIKE %word% 扫描。

通道二：sqlite-vec 余弦（vecIndexer.ts）

按三元组定位 vec 表，查询向量 Float32 blob 执行 KNN（k=100）；任何失败（模型缺失 / 网关挂 / 维度不匹配）仅降级该通道为空并告警，绝不失败整个搜索（AC-02）。事实写入时向量索引为事务提交后的异步微任务，异常静默吞掉——写路径永不因 embedding 阻塞。

融合与排序公式

rrf(d) = Σ 1 / (60 + rankc(d))
RRF 倒数排名融合，k=60；平分按 id 字典序保证确定性
score = rrf × 0.5days / halfLife + (entityHit ? 0.1 : 0)
days = 距 last_accessed_at 天数；halfLife 默认 30 天；pinned 豁免衰减（因子恒 1）
  • 实体加权：取空间内全部实体（name + aliases），查询文本小写 includes 命中后经关联表反查 fact 集合，命中者 +0.1。
  • 触达反馈：检索命中调用 touch → access_count+1、刷新 last_accessed_at，反哺衰减公式（用得越多忘得越慢）。
  • 留痕回放：六阶段每阶段候选 id 列表 + 总时延写入 retrieval_traces，Dashboard 轨迹页可逐步回放定位召回丢失发生在哪一阶段。
  • 质量门禁：合成基线 200 事实 × 40 查询，默认参数 R@5 ≥ 0.85 作为 core 测试门禁。
06

精炼管线

refine/*.ts · L0 → L1/L2/L3

L1 事实抽取 l1Extract.ts — 双策略 + 自动降级

LLM 策略 写路径恰好一次 LLM 调用

对话转写 [role] content 拼接（截断 20000 字符），要求仅输出 JSON：{"facts":[{"action":"ADD|UPDATE","content":…,"supersedes":…}]}。Zod 校验（content 1–2000 字符、最多 50 条）；parseLlmJson 兼容小模型用 markdown 围栏包裹 JSON 的输出。

启发式策略 离线兜底

仅扫 user 消息：^记住：… / ^remember:… → ADD；以后用 X 不用 Y → 修正类 ADD。

降级链：LLM 输出脏（DegradedSignal / SyntaxError）→ 自动切换启发式并置 degraded:true，任务永不因此失败。UPDATE 通过 content 精确匹配库存事实走 DAO supersede；ADD 天然享受 5 分钟去重窗口（同 space + 同 SHA-256 + active + 窗口内 → 直接 deduped）。

L2 场景索引 l2Summarize.ts — 规则式，零 LLM

标题 = 首条 user 消息截 40 字符；摘要 = 全部消息以中文分号连接截 200 字符；token_estimate = ceil(字符数/4)。

L3 用户画像 l3Profile.ts — 单次 LLM + 版本化追加

单次 LLM 调用输出更新后的画像 Markdown；能力关闭或输出为空则整条跳过。落库为 scope_key 下 version+1 新行（唯一索引 (scope_key, version)）——注入时取最新版全文，实现逐轮字节稳定。

衰减扫描 decayScan.ts — 与评分同公式

factor = 0.5 days / halfLife   遗忘阈值 0.05
默认半衰期 30 天 ⇒ 约 129.6 天未访问进入候选；pinned 跳过；dryRun 支持预览

候选置 status='forgotten' + 删 FTS 行（物理保留可恢复），逐条发布 decay.forgotten 事件。

双协议 IR 适配 adapters/ — 互转在 IR 层，透传在字节层

代理不做 Anthropic↔OpenAI 协议互转：进什么协议出什么协议。adapter 把两种协议解析为统一 AgentContext（model/stream/systemBlocks 只读视图/tools/raw 深克隆），在 IR 的三个注入槽位（systemPrefix / systemSuffix / toolsAppend）上打注入，再各自序列化回原生协议。

往返纪律：injections 为空时 serialize(parse(x)) === x 深相等 —— tool_use / tool_result / cache_control / thinking / tool_calls 等原生块逐字节保留。

  • Anthropic：system 字符串或块数组 → 重组为 [prefix…原生块…suffix]；注入文本块不带 cache_control。
  • OpenAI：找 system 消息拼接 content；无 system 消息则 unshift 新建；流式请求强制加 stream_options.include_usage 以捕获用量。
  • OpenAI 流处理：JSON data 行（非 event:/data: 帧）单独用 TransformStream 逐行解析；工具调用分片按 index 聚合后合并为 [tool_call: name(args)] 文本。
  • 畸形防御：非流式 Anthropic 响应中丢弃畸形 thinking 块再提取文本。

  • Token 预算：maxTokens 默认 2000，贪心累加，装不下的块整块丢弃不截断，高优先级保留。
  • 前缀稳定性监控：注入前缀是空间数据（profile/scenarios/skills）的纯函数，规范化为 canonical JSON 后取 MD5。逐轮 MD5 恒定 ⇒ 上游 KV-cache 前缀命中；变化 ⇒ 前缀击穿信号（Dashboard 红/绿指示）。三源缓存 TTL 30s。

L0 写回（防二次方膨胀）

  • 当前轮提取：Agent 每轮重发全量历史，因此只取「最后一条 assistant 之后」的消息（user 追问 + tool_result），再拼上本轮捕获的 assistant 文本——否则旧轮次每轮重复入库导致 L0 二次方膨胀。轮终结符 = 不含 tool_use 块的干净 assistant。
  • 脱敏时机：enqueue 时（离开代理进程前）对每条 content 执行 redact，再 POST 给 core；脱敏只作用于写回内容，不影响转发上游的请求。
  • 可靠性：fire-and-forget，enqueue 立即返回绝不抛错；有界退避重试 [200, 800, 2400] ms 共 4 次尝试；耗尽进内存死信表；drain() 优雅停机排水。
  • core 侧配套：L0 写入路径再做信封剥离（8 个 IDE 注入标签如 system-reminder/attached_files 等仅从 user 消息剥离，剥空回退原文）+ 8192 字符分块 + 事务批量插入 + 发布 l0.appended 事件。

横切设计原则

贯穿全部七个包
① 离线优先 · Fail-open

默认 provider 为确定性 Mock；LLM 缺失→启发式精炼；embedding 失败→FTS 照常；sidecar 失败→回退默认；写路径（L0/L1）永不因外部依赖阻塞或失败。

② 字节级透明

无注入时请求体深相等往返；SSE 客户端流字节级透传；原生块（thinking/tool_use/cache_control/tool_calls）逐字节不动。

③ 不可变叙事

L1 编辑即 supersede（链式 superseded_by + lineage API）；遗忘即状态翻转（可 recover）；物理删除仅发生在空间级联与 DLQ。

④ 前缀稳定（KV-cache 友好）

注入只加 systemPrefix/toolsAppend；前缀是空间数据的纯函数；逐轮 MD5 恒定即缓存命中，变化即击穿告警。

⑤ 防重防膨胀

写回只取当前轮（防 L0 二次方膨胀）；mem: 只匹配当前 prompt（防历史命令劫持）；L1 五分钟去重窗口；精炼任务按 session 去抖。

⑥ 热更新

config 表 + config.updated 事件 + worker 每次执行重读策略；配置变更无需重启即改变精炼策略与能力状态。

⑦ 可观测

检索六阶段留痕可回放；事件全量持久化可 replay；注入逐轮记录；DLQ 死信可见；会话记忆 diff。

⑧ 可逆接入

onboard 一律备份 + created 标记 + restore；冲突不静默覆盖；密钥永远留在 Agent 客户端侧透传。
